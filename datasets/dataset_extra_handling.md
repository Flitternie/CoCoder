# Dataset Extra Handling

## Automatic Data Protection Mechanism

`workspace_builder.py` has two built-in layers of protection when building the workspace, ensuring that data files in source code directories are not lost due to Agent rewrites:

1. **Full copy of non-`.py` files** — `os.walk` traverses the entire repo and automatically copies all non-`.py` files (csv, txt, json, pickle, templates, locale, etc.) to the workspace. The Agent is only responsible for generating `.py` source code; data files always come from the baseline.
2. **`.py` data file overrides** — Some data files use the `.py` extension (e.g., `zxcvbn/frequency_lists.py`). Glob patterns configured in `config/copy_py_overrides.yaml` cause matching `.py` files to be copied directly rather than handed to the Agent for generation.

---

## Configured copy_py_overrides.yaml

```yaml
CodeProjectEval/djangorestframework-simplejwt:
  - "rest_framework_simplejwt/token_blacklist/migrations/*.py"

CodeProjectEval/zxcvbn:
  - "zxcvbn/frequency_lists.py"
  - "zxcvbn/adjacency_graphs.py"
```

## Per-Project Extra Handling Details

### DevBench/lice: Remove `--cov-fail-under=100`

- **Action**: Removed the flag from test commands in `config.json` (`unit/check/acceptance` scripts all adjusted).
- **Reason**: The original reference implementation only achieves ~`80.59%` coverage, making `100%` unreachable. This causes all-tests-pass runs to still be marked as failures.
- **Impact**: Evaluation now uses test case pass/fail as the criterion, without enforcing a coverage threshold. Only this project had this constraint; other projects are unaffected.

### CodeProjectEval/zxcvbn: Lock Baseline Data Files

- **Action**: `zxcvbn/frequency_lists.py` (word lists) and `zxcvbn/adjacency_graphs.py` (keyboard adjacency graphs) are copied directly via `copy_py_overrides.yaml`, not generated by the Agent.
- **Reason**: Unit tests have hard dependencies on specific data values — `matching_test.py` requires `dictionary_match('wow')` to have `rank == 322`; `scoring_test.py` requires `qwerty` average degree to equal `4.595744680851064`; spatial matching tests hardcode specific turns/shifts values.
- **Impact**: Even if the Agent produces correctly formatted output, any inconsistency in rank or adjacency details causes widespread failures across matching/scoring/zxcvbn test suites.

### CodeProjectEval/zxcvbn: Fix `config.json` Coverage Target and `requirements.txt`

- **Action 1**: `config.json` — `--cov=xmnlp` → `--cov=zxcvbn` (both `unit_test_script` and `check_test_script`).
- **Reason**: `xmnlp` is a different project's module name, copy-paste residue. Coverage collector never imported `xmnlp`, producing empty reports and `CoverageWarning: No data was collected`.
- **Action 2**: `requirements.txt` — `pytest==3.5.0` → `pytest`, removed the version pin.
- **Impact**: Test pass/fail results were always correct; only the coverage report was broken. `pytest==3.5.0` is incompatible with the current environment; removing the pin lets it use the already-installed pytest.

### DevBench/ArXiv_digest: Add `requests` to `requirements.txt`

- **Action**: Appended `requests` to `docs/requirements.txt`.
- **Reason**: The baseline `query_arxiv.py` uses `urllib.request`, so `requests` was not listed in the original requirements. However, Agents frequently generate code that uses the `requests` library instead. Without `requests` installed, all unit tests fail at collection time with `ModuleNotFoundError: No module named 'requests'` (symptom: `collected 0 items / 6 errors`).
- **Impact**: Ensures Agent-generated implementations using either `urllib` or `requests` can be tested. Does not affect the baseline.

### CodeProjectEval/trailscraper: Relax `boto3`/`moto` Version Pins

- **Action**: `requirements.txt` — `boto3==1.26.54` → `boto3>=1.26.54`, `moto<4.0` → `moto>=3.1.19,<5.0`.
- **Reason**: `setup_shell_script.sh` runs `pip install -r requirements.txt` without a venv, so the pinned `boto3==1.26.54` downgrades the conda env's botocore from 1.42.x to 1.29.x. This removes the `bedrock-runtime` service definition, causing all subsequent Bedrock API calls to fail with `UnknownServiceError`.
- **Constraint**: `moto<5.0` is required because trailscraper tests use `from moto import mock_s3`, which was removed in moto 5.0 (replaced by `mock_aws`). moto 4.x still exports `mock_s3`.
- **Impact**: Prevents trailscraper's setup from polluting the global Python environment. Does not affect test behavior.

### CodeProjectEval/djangorestframework-simplejwt: Lock Historical Migration Files

- **Action**: `rest_framework_simplejwt/token_blacklist/migrations/*.py` are copied directly via `copy_py_overrides.yaml`.
- **Reason**: Migration tests execute actual migrations from old to new versions and verify results (`populate_jti_hex` data migration, `BigAutoField` type assertions, `makemigrations --check` consistency checks).
- **Impact**: Any inconsistency in the historical migration dependency chain or field types causes migration test failures.
